1. ARCHITECTURAL OVERVIEW & DESIGN PRINCIPLES
====================================================================================================
The flowCTRL database is structured on PostgreSQL 18 utilizing Prisma ORM as the authoritative
object-relational mapping and migration engine. The relational schema is engineered to satisfy
enterprise requirements for:
  • Primary Key Security: Collision-resistant CUIDs (Collision-resistant Unique Identifiers)
    and composite primary keys prevent enumeration attacks common with auto-increment integers.
  • Relational Integrity: Strict Foreign Key constraints enforced directly at the PostgreSQL engine level
    using explicit `ON DELETE CASCADE` or `ON DELETE SET NULL` policies.
  • Performance Optimization: Multi-column composite unique constraints, B-Tree indexes on all foreign
    keys, search filters, status codes, and timestamps.
  • Storage Optimization: Variable text (`VARCHAR` / `Text`), JSONB (`Json`) for dynamic structured
    attributes (AI feedback, ATS metadata, custom settings), and integer/float primitives.
  • Security & Privacy: Cryptographic hash storage for passwords (bcrypt 10-round salt), tokenized
    session credentials with automatic expiration checking, and centralized audit logging (`SecurityLog`,
    `AuditLog`).

2. GLOBAL ENUM SPECIFICATIONS
====================================================================================================

2.1 Role (Identity & Authorization)
    Values:
      - GUEST       : Unauthenticated visitor / preview access.
      - USER        : Standard registered developer / engineer.
      - MENTOR      : Verified technical advisor with mentorship capabilities.
      - RECRUITER   : Verified talent partner with job posting and candidate screening privileges.
      - COMPANY_REP : Official enterprise corporate representative.
      - ADMIN       : Platform system administrator.
      - SUPER_ADMIN : Root platform operator with unrestricted governance rights.

2.2 WorkMode (Job Opportunity Classification)
    Values:
      - REMOTE : 100% remote / distributed employment.
      - HYBRID : Split on-site and remote work arrangement.
      - ONSITE : 100% physical on-site employment requirement.

2.3 ApplicationStatus (Job Pipeline Tracking)
    Values:
      - APPLIED      : Application submitted by candidate to employer.
      - SCREENING    : Automated ATS parsing or recruiter review phase.
      - INTERVIEWING : Active technical or behavioral interview stages.
      - OFFERED      : Formal offer of employment extended.
      - REJECTED     : Candidate not selected for this position.
      - WITHDRAWN    : Application retracted by candidate.

2.4 IssueStatus (Project Tracking & Collaboration)
    Values:
      - TODO        : Task / issue created and awaiting triage or commencement.
      - IN_PROGRESS : Active development or debugging in flight.
      - DONE        : Verified and merged to completion.

2.5 IssuePriority (Triage & Issue Urgency)
    Values:
      - LOW    : Minor enhancement, non-blocking bug, or chore.
      - MEDIUM : Standard priority task or expected feature work.
      - HIGH   : Important milestone blocker or high-impact defect.
      - URGENT : Critical outage, security vulnerability, or production blocker.

4.1 Table: User
----------------------------------------------------------------------------------------------------
Purpose:
  The authoritative root entity for identity, access governance, and ownership across the entire
  flowCTRL platform. Every profile, preference, roadmap, session, resume, and membership connects
  back to this model.

Columns:
  • id             : String (cuid) | PK | NOT NULL | Default: cuid()
                    Unique collision-resistant primary key.
  • name           : String        | NULL
                    Full legal or display name provided by user or OAuth identity.
  • email          : String        | UNIQUE | NULL
                    Primary normalized lowercase email address used for signin and verification.
  • emailVerified  : DateTime      | NULL
                    Timestamp indicating when email ownership was confirmed.
  • image          : String        | NULL
                    Direct avatar image URL (NextAuth compatibility).
  • password       : String        | NULL
                    Bcrypt password hash (10 salt rounds). Null for pure OAuth accounts.
  • role           : Enum (Role)   | NOT NULL | Default: USER
                    Role-based access level (GUEST, USER, MENTOR, RECRUITER, COMPANY_REP, ADMIN, SUPER_ADMIN).
  • status         : String        | NOT NULL | Default: "ACTIVE"
                    Account lifecycle status: "ACTIVE", "SUSPENDED", "DEACTIVATED".
  • headline       : String        | NULL
                    Legacy direct profile headline (preserved for zero-migration compatibility).
  • bio            : Text          | NULL
                    Legacy biographical summary (preserved for zero-migration compatibility).
  • location       : String        | NULL
                    Legacy geographical location string.
  • createdAt      : DateTime      | NOT NULL | Default: now()
                    Account creation timestamp.
  • updatedAt      : DateTime      | NOT NULL | Auto-updated on record change
                    Last modification timestamp.

Indexes & Constraints:
  • Primary Key : `id`
  • Unique      : `email`
  • Index       : `@@index([email])`
  • Index       : `@@index([role])`
  • Index       : `@@index([status])`
  • Index       : `@@index([createdAt])`

Connected Relationships:
  • UserProfile?            : 1-to-1 relation to `UserProfile` (Cascade on delete).
  • UserPreference?         : 1-to-1 relation to `UserPreference` (Cascade on delete).
  • UserSession[]           : 1-to-many relation to `UserSession` (Cascade on delete).
  • Account[]               : 1-to-many relation to `Account` (OAuth provider links).
  • Session[]               : 1-to-many relation to `Session` (NextAuth sessions).
  • SecurityLog[]           : 1-to-many relation to `SecurityLog` (Login/audit history).
  • UserSkill[]             : 1-to-many relation to `UserSkill` (Selected skills).
  • Roadmap[]               : 1-to-many relation to `Roadmap` (Authored custom roadmaps).
  • MentorProfile?          : 1-to-1 relation to `MentorProfile` (Mentorship profile).
  • Resume[]                : 1-to-many relation to `Resume` (Uploaded CV artifacts).
  • ResumeAnalysis[]        : 1-to-many relation to `ResumeAnalysis` (ATS scoring results).
  • SavedJob[]              : 1-to-many relation to `SavedJob` (Bookmarked job vacancies).
  • JobApplication[]        : 1-to-many relation to `JobApplication` (Submitted applications).
  • Project[]               : 1-to-many relation to `Project` via relation "ProjectOwner".
  • ProjectMember[]         : 1-to-many relation to `ProjectMember` (Workspace team memberships).
  • Issue[] (created)       : 1-to-many relation to `Issue` via relation "IssueCreator".
  • Issue[] (assigned)      : 1-to-many relation to `Issue` via relation "IssueAssignee".
  • Notification[]          : 1-to-many relation to `Notification` (Platform alerts).
  • UserRoadmapProgress[]   : 1-to-many relation to `UserRoadmapProgress` (Topic tracking).
  • AuditLog[]              : 1-to-many relation to `AuditLog` (Administrative audit trail).
  • UserMembership?         : 1-to-1 relation to `UserMembership` (Active plan & tier).
  • MembershipHistory[]     : 1-to-many relation to `MembershipHistory` (Subscription audit).
  • MembershipTransaction[] : 1-to-many relation to `MembershipTransaction` (Payment ledger).

4.6 Table: UserSession
----------------------------------------------------------------------------------------------------
Purpose:
  Production custom session management and cybersecurity session tracker. Enforces absolute
  session expiration, cryptographic CSRF token binding, device profiling, and instantaneous
  session revocation ("Log Out from All Devices").

Columns:
  • id           : String    | PK | NOT NULL | Default: cuid()
  • userId       : String    | FK | NOT NULL
                   Foreign key referencing `User.id`.
  • sessionToken : String    | UNIQUE | NOT NULL
                   Opaque high-entropy 256-bit session token stored in HttpOnly cookie.
  • ipAddress    : String    | NULL
                   Client IP address recorded at session issuance.
  • userAgent    : String    | NULL
                   Full browser User-Agent header string.
  • deviceType   : String    | NULL | Default: "Desktop"
                   Parsed device class: "Desktop", "Mobile", "Tablet", "Unknown".
  • browser      : String    | NULL
                   Parsed browser family (e.g. "Chrome", "Firefox", "Safari").
  • os           : String    | NULL
                   Parsed operating system (e.g. "Windows", "macOS", "Linux", "iOS").
  • revokedAt    : DateTime  | NULL
                   Timestamp when session was explicitly revoked. Null if active.
  • lastActiveAt : DateTime  | NOT NULL | Default: now()
                   Timestamp of user's most recent API interaction (throttled).
  • expiresAt    : DateTime  | NOT NULL
                   Hard expiration date (default: 7 days from creation).
  • createdAt    : DateTime  | NOT NULL | Default: now()
  • updatedAt    : DateTime  | NOT NULL | Auto-updated

Indexes & Constraints:
  • Primary Key : `id`
  • Unique      : `sessionToken`
  • Index       : `@@index([userId])`
  • Index       : `@@index([expiresAt])`
  • Index       : `@@index([revokedAt])`
  • Foreign Key : `userId` -> `User.id` (ON DELETE CASCADE)

Connected Relationships:
  • user : Many-to-1 parent relation referencing `User`.

6. REFERENTIAL INTEGRITY, CASCADING RULES & INDEXING STRATEGY
====================================================================================================

6.1 Cascading Delete Protocol (GDPR & Data Cleanliness):
  When a user account (`User`) is deleted:
  • Primary profile, preferences, custom roadmaps, and sessions are immediately PURGED (Cascade).
  • Uploaded resume artifacts and analyses are immediately PURGED (Cascade).
  • Saved jobs and job applications are immediately PURGED (Cascade).
  • Security logs and membership history are PURGED (Cascade).
  • Workspaces owned by the user are PURGED (Cascade).
  • Issues authored or assigned to the user have their foreign keys safely preserved with SET NULL,
    preventing corruption of team collaboration repositories.
  • Administrative AuditLog entries retain their immutable activity record with SET NULL on the actor ID.

6.2 Indexing & Query Acceleration:
  Every relational lookup path in flowCTRL is indexed using PostgreSQL B-Tree indexes:
  • All foreign keys (`userId`, `companyId`, `roadmapId`, `projectId`, `skillId`, `jobId`, `planId`).
  • Filterable enumerations and status columns (`role`, `status`, `workMode`, `accessLevel`, `read`).
  • Composite unique constraints preventing duplicates:
    - `[provider, providerAccountId]` in Account
    - `[identifier, token]` in VerificationToken
    - `[userId, skillId]` in UserSkill
    - `[jobId, skillId]` in JobSkill
    - `[userId, jobId]` in SavedJob
    - `[userId, roadmapSlug]` in UserRoadmapProgress
    - `[projectId, userId]` in ProjectMember
  • Temporal / chronological query indexes (`createdAt`, `expiresAt`, `revokedAt`) for efficient
    session revocation sweeps and audit log pagination.

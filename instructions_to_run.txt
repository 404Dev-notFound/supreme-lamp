How to run FlowCTRL locally (backend + frontend)
Below are the exact folder paths (absolute for your machine) and the commands you need to execute, in the order they should be run.

2️⃣ Install root‑level dependencies (optional but recommended)
The repository contains a top‑level package-lock.json that is only used for the monorepo tooling. Run once:

powershell


npm ci   # or `npm install` if you prefer
3️⃣ Set up environment variables
Both apps read a .env file at the repo root (the backend also reads .env in its own folder).
Create it now (you can copy the example if one exists):

powershell


# repository root
New-Item -Path . -Name ".env" -ItemType File -Force
Add at least the following variables (replace the values with whatever you need for local dev):

dotenv


# .env   (repo root)
PORT=5000                     # backend HTTP port
NEXT_PUBLIC_API_URL=http://localhost:5000   # URL the frontend will call
# (any other secrets you need, e.g. JWT secret, DB connection string, etc.)
Tip – the backend also loads .env from apps/backend/, so you can place the same file there if you prefer:

powershell


Copy-Item .\.env .\apps\backend\.env -Force
4️⃣ Install backend dependencies
powershell


cd apps/backend
npm ci
5️⃣ Run the backend (development mode)

The backend now listens on http://localhost:5000 and exposes routes such as /api/health.

8️⃣ (Optional) Allow the network URL in development
If you access the app from another device on the same LAN, you’ll see a warning about cross‑origin dev resources. Add the host to next.config.ts once, then restart the frontend:

ts


// apps/frontend/next.config.ts
import type { NextConfig } from 'next';
const nextConfig: NextConfig = {
  allowedDevOrigins: ['192.168.64.1'], // add any other IPs you need
};
export default nextConfig;
9️⃣ Stopping the servers
Press Ctrl +C in each terminal to stop the backend and frontend respectively.
